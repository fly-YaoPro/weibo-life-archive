# 首图物件点击：制作与最小验收

## 先读完成图，再标定

光点只是提示，点击区域须覆盖实际物件的主要可见部分。不要用44px光点代替物件，不按生图提示词猜位置，不复用别人的物件或坐标。

在最终生成的完整原图中为每件物件标定：`x/y`为光点位置，`bounds:{x,y,width,height}`为可点矩形，全部使用原图0—100百分比。矩形尽量覆盖可见主体，留在自身轮廓内，不碰邻居；若物件交叠，选其独立可见部分，不用巨型矩形抢占别的物件。光点放在自己的矩形内。

Agent写标定表（不是让用户算坐标），示例仅说明格式，不是可复用的实际位置：

```json
{"h-book":{"x":55,"y":60,"bounds":{"x":45,"y":45,"width":20,"height":30}}}
```

```bash
python scripts/calibrate_scene.py --source /工作区/source --regions /工作区/scene-regions.json
```

脚本要求覆盖全部热点、无重叠、光点在区域内，保存与首图SHA256绑定的标定信息，并备份修改前story。它不能判断画中的书在哪里：看图是Agent责任。构建校验会拦截换图后沿用旧指纹的区域；重生成或替换首图后必须重新看图标定，不能只刷新指纹。

模板让背景、点击区域、光点共用同一图片坐标平面，完整等比显示；悬停视差也一起移动。`bounds`为真正可点的透明原生按钮，光点只负责视觉，小记锚在光点。不要单独使用cover裁切背景、把按钮放在视口坐标里、用透明遮罩覆盖场景，或把物件切换成导航链接。

旧story仅有x/y仍能打开，作为兼容回退，不代表物件已标定。使用新版制作/重做时补齐全部bounds。检查目录和物件指向同一来源、主题或日期，不改原有叙事。

## 只补首图的最小浏览器验收

沿用现成浏览器能力；不为此强行安装整套新环境。构建/部署后选可打开的产物，至少宽屏约1280×720、窄屏约390×844各一轮：

1. 等首图解码完成并关闭欢迎层。先看图认物件，不通过目录找按钮来代替实点。
2. 每件物件点主体中心，再点区域内一个远离星标的位置；两处都应打开同一正确小记。点空白处不应误开邻居。变换视口后重复，不能只测试按钮中心。
3. 对每个小记点“翻到这段记忆”，确认原有主题/日期正确，能回首图。检查Escape关闭、键盘聚焦和目录兜底。
4. 检查窄屏小记在视口内、入口不遮挡物件；触摸目标尽量达44px。小物件无法扩大且会抢邻居时保留准确区域和文字目录，不暗中扩大到其他对象。

记录所测产物、视口、热点ID、实际点击位置和结果。只通过首图检查就写`scene_clicks_verified`，不能把全站`browser_interactions_verified`改为true。静态构建或发布finished也不能证明点击通过。环境确实无法打开产物时保留未验证说明，不声称已实测；不阻断其他离线工作，不假造回执。其余全站浏览器测试仍按需，不恢复漫长全面验收。
