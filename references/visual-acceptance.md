# 开发后的实际视觉验收

修改模板后，必须打开最新构建的HTML并截图，再和项目示例对照。代码检查、CSS属性不同、旧截图或工具返回成功都不能代替看实际画面。按“打开 → 对照 → 写差距 → 修正 → 重建 → 再打开”循环，直到当前差距处理完；不要只承诺以后再看。

## 可复用截图脚本

```bash
python scripts/visual_review.py /工作区/delivery/最新手账.html --output /工作区/visual-checks --browser-executable /实际Chromium路径
python scripts/check_flip.py /工作区/delivery/最新手账.html --output /工作区/flip-checks --browser-executable /实际Chromium路径
```

用隔离浏览器、file://禁网打开真实文件。保存1440×900和390×844的回看、年历开头、年历格子、来信以及翻页前/中/后三帧。安装了Pillow时生成与assets/cases的并排对照图。脚本只提供证据，不自动宣称美观通过；Agent仍要实际打开PNG看。

豆包local-pc使用实际宿主浏览器工具执行相同动作。远程文件不能在本地浏览器直接打开时，在文件所在宿主渲染截图，或通过实际文件入口打开；不能把“排队打开”说成已检查。

参考图的人物、照片、文字、日期不复制到用户手账。按用户当前要求保留一屏回看、顶部翻页、自适应范围年历与记录节奏、年历开头的长卷摘要、可选来信与可编辑计划；不恢复底部分页和巨大单月空页，简洁的实际范围/精选标识保留。图像质量也要单独核对：测试插画不能证明真实微博照片或生成图已达到成品质量。

## 要实际检查的差距

- 主图、标题、正文、小片段是否有清楚主次；短正文不要留出一整块没有用途的空白。
- 纸本不能漂移成棕黄旧纸；磨砂不能只换背景却保留同款纸框。两套各自贴近示例材质且保持明显区分。
- 标题/日期没有孤字或拆词；装饰不压字、图片不截主体，手机另看。
- 年历摘要在最开头，长年度小记按需展开，不另有数据长卷导航。空数据不伪造成活动，年份高亮来自实际已收录记录。
- 翻页中间帧没有旧文字透到新图片上、镜像字、半页硬裁切、重复书脊或整体背景闪白。页面宽度在转动时保持原排版，只转实际页片。
- 数据长卷和来信滚动后所有元素能出现。折叠details内的元素可能有DOM矩形却实际不可见；截图/等待必须排除未展开内容，展开后另验，不能因此判失败或漏看。

## 保存结论

在工作区记录参考文件、被检查的HTML、视口、实际截图路径、发现的问题和修复后的观察。说明未验证项，不给未经支持的“完美/完全一致”结论。验收记录及截图留工作区；默认保留完整离线目录，可加便携HTML；双风格各自验收。

封面另验：左相纸下有开场白和有来源的人物画像；右侧不只是一个居中标题，须有导语与实际年份片段。画像没有编年龄/职业/人格类型，手机封面内容通过连续页完整呈现，不缩字硬塞。

独立HTML打包后再执行最终对照；内页开发时可先打开built/index.html排查，但交付文件仍要单独打开一次。视觉复查由Agent使用读图工具完成，例行布局修正不需要再向用户申请确认。中等宽度也检查，画像应能通过续页完整读到。
