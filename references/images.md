# 图片完整性：全部配图、单一尺寸

仅核对实际收录的 records.json，不对未入选候选下载图片。沿用4.2的精选配额与高清优先单尺寸：一条入选微博有12张配图，应保存12张，每张只需一个实际有效的本地文件，thumb_path/large_path/original_path可指向同一文件。不要求为了验收重复下载小图、大图。

## 源图盘点

读取平台pic_num、完整pic_ids或已核验详情/授权导出清单，填写expected_image_count、image_count_basis和image_inventory_status。数量未知保留null/unknown，清单不足为partial；不能用当前images长度自行证明总数。明确无图才填0并记录依据。补查仅针对入选且盘点未知/不齐的记录，可信的已完成盘点与缓存继续复用。

每项images保留image_id（真实PID或源图片标识）、origin、source_url、download_status和本地路径。超过9张的帖子同样枚举完整；视频封面继续放video.covers，不计入普通配图总数。失败图片保留条目与原因，不删条目或换史料来通过检查。

## 下载与静态检查

manage_media plan生成整批清单，download默认3路并发（--workers 1串行，最多6），同URL只请求一次，命中校验通过的缓存不再下载。高清地址选择与下载后压缩按manage_media默认参数执行；并发不降低取图规格。列表分页的间隔与可见范围判断保持不变。限制响应或预算不足即停止新任务及重试；已在途请求不能瞬间撤回，由超时结束，成功结果可保留续用。

运行 python scripts/audit_images.py /工作区/source。检查源数量与枚举清单一致、图片ID唯一、每项已保存且最佳本地文件可识别。多个尺寸角色引用同一文件是正常单尺寸策略。检查器不联网，不代替源端核对、完整解码或人工看图。AVIF等检查器尚不支持的格式可通过正常读图工具转为可验证副本，保留来源与转换说明。

check_project、build_journal和独立HTML的共享运行时契约执行同一完整性门禁。数量未知、缺图、坏图不能标成完成版；保留正文、断点和缺口说明供补采。已有老数据需补盘点字段，不重新抓取整个账号。

当已收录真实配图时，总览和主题页至少有一处展示对应来源照片，不能把全部照片只藏进年历。不强行给每页配图，纯文字记录照常保留。首屏/结尾生成插画独立放decorations/，不得冒充历史照片。


候选库存在较大的已观察源图总数时，实际收录记录不得把期望图数改小来通过检查；audit_images会对比同ID候选值。story_tools index输出仅入选缺项队列；详情补采的实时获取方法仍需正确Harness验证。

## 压缩统计与整册预算

下载结果的compression及source/compression-report.json记录已知原始字节、输出字节、节省比例及未压缩原因；断点复用保留统计。旧缓存没有原始字节时unknown_original_urls明确标记，不伪造压缩率。交付文字使用“压缩后的真实配图”，不把original_path字段当未压缩原图证明。

journal_run在打包前仅对built_dir中的交付副本应用整册素材目标，默认24MiB（--book-max-mb）；包含照片、封面、插画、头像和音频。不改采集源、不减少图数。超出时最多两档（1024/Q65，再按剩余预算选择640—960长边/Q60），3路并发，仍超出保留全部素材并报告target_met=false，优先目录/资源存储发布，不循环降质。每个artifact.media_budget返回前后体积、节省比例、实际档位与目标是否达到。单HTML另有Base64约三分之一体积增量，预算目标不是宿主发布限额。
