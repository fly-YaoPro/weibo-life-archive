# 页面框架与构建

优先使用 assets/starter，不让 Agent 每次从零写页面。代码负责稳定排版、日历、计划、翻页、来源弹窗与长图；Agent负责真实素材选择和叙事。明确是模板缺陷时允许最小修复，保留原模板并验证两套风格和手机，不禁止所有前端修改，也不为通过检查改假数据。

## 三个板块

- 回看：overview封面，A主图短记、B双图对照、C摘句解读。主题数随有效素材，不重复同一段。顶部翻页，短屏拆续页，装饰不盖文字或照片主体。
- 日历：统计摘要并入开头；默认打开有记录的最近日期。稀疏年只铺有记录的月份，日期可点、搜索跨年、原帖图片可放大。计数区分已收录/全部已核验，不显示巨大空日历。
- 后续计划：可选的未来来信 + 必填 plans。计划支持月份、编辑、勾选、添加、删除、本地持久化、JSON导入/导出与恢复。保留既有手动修改，不用只读 wishes 替代。

可选 scene 入口仅在明确需要、已生成并验证场景时显示，不改变三个主板块。歌曲推荐 story.song 与可选实际音源 story.bgm 分开。

## 最小内容结构

```json
{
  "overview": {"headline":"具体标题","text":"200字内回顾","source_ids":["真实ID"],"image_paths":["images/照片.jpg"]},
  "themes":[{"id":"t1","title":"具体变化","text":"40—100字短记","source_ids":["真实ID"],"layout":"A","image_paths":["images/照片.jpg"]}],
  "plans":[{"id":"p1","title":"具体可选小事","month":"2027-01","reason":"与记录有关的依据","source_ids":["真实ID"]}],
  "share":{"entries":[{"source_id":"真实ID","title":"短标题","text":"来自同一记录的提炼"}]}
}
```

按数据契约补 evidence。overview.opening/portrait可增强封面，不把证据不足的画像设为必填。没有图的章节用文字设计；如果归档存在真实照片，不能让回看全部无图。

## 生成

source与built为平级新目录。build_journal会检查图片完整性、身份/日期/来源、叙事重复、计划非空，复制模板及全部归档图片，生成显示数据。journal-assets.js令离线目录分享可读本地图；pack_html再把引用资源内嵌成单文件。目录交付保留原始记录与多尺寸素材，不复制浏览器profile/cache/凭据。

先修源数据或模板中的实际错误，重建到新目录。不要直接改打包后的HTML导致源与产物不同步。实际打开纸本/磨砂与独立HTML，按视觉验收复核。
