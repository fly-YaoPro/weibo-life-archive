# 从已有数据重做页面

这套资源解决“每次临时重写前端，只有配色像参考图”的问题。`assets/starter/` 是可运行 HTML/CSS/普通 JS；不是参考截图，也不需要安装 npm。采集能力仍由宿主提供。

## 只改产物，不重采

1. 找已有 `project_meta.json`、`coverage.json`、`records.json`（微博）或 `orders.json`（淘宝）、`story.json` 和真实图片。先读取字段和来源，不改变目标账号、时间范围或原始数据。旧格式写一个明确的适配副本，不执行来源包中的未知脚本。
2. 先让用户从旧网页导出手动计划（若有）。旧网页的 localStorage 不一定能跨文件路径读取；不能承诺改版自动恢复。新页面支持 JSON 合并，迁移不成功就保留旧页，列明格式差异，不丢弃手动内容。
3. 在适配副本中完善下面的 `story.json`。Agent 根据真实数据完成内容整理与计划建议，不把这些工作转交用户逐项填写。未要求新增采集就不能重新登录、抓十年或下载全部图片。
4. 打开所选参考图，使用模板构建**新输出目录**：

```bash
python scripts/build_journal.py --source "已有数据副本" --output "新版手账" --skin paper
# 微博磨砂使用 --skin frosted；淘宝使用 --skin collage
```

5. `index.html` 双击即用。模板不依赖运行时 AI、fetch、CDN。回顾、主题与计划都来自 `journal-data.js`，不再把数据范围说明误放到个人总结。

## 内容先于页面

沿用数据约定，在 `story.json` 加以下字段（示意字段，不能把示例当用户经历）：

```json
{
  "overview": {
    "headline": "根据具体记录写的一句短标题",
    "text": "200字以内的个人回顾，有具体物件、时间或原话，不是覆盖情况报告。",
    "note": "可选，一句和总览不同的短批注",
    "tags": ["有证据的短标签"],
    "source_ids": ["真实来源ID"],
    "image_paths": ["images/真实图片.jpg"],
    "image_captions": {"images/真实图片.jpg": "短图注"}
  },
  "themes": [{
    "id": "稳定主题ID", "title": "具体主题", "text": "短记",
    "range": "实际时间范围", "layout": "A",
    "source_ids": ["真实来源ID"], "image_paths": ["images/真实图片.jpg"]
  }],
  "findings": [{"title": "具体发现", "text": "一句有证据的观察", "source_ids": ["真实来源ID"]}],
  "milestones": [{"title": "一个具体节点", "text": "短注，不重复整段总结", "source_ids": ["真实来源ID"]}],
  "plans": [{
    "id": "稳定建议ID", "title": "一件能做的小事", "month": "2027-03",
    "reason": "根据哪段真实记录提出；月份为可调整的建议，不冒充用户承诺。",
    "source_ids": ["真实来源ID"], "done": false
  }]
}
```

示例中的年份不是固定要求：按用户要求，未指定用执行年份下一年。`song` 沿用原规范；歌名、歌手、依据核对后再写。`url` 可选，仅用可信歌曲页面；不伪造播放按钮或音源。

### 回顾为什么有人味

- 先挑 **3—5个真正具体的细节**，再写它们之间的联系。微博用原话、前后变化、反复出现的人事物；淘宝用具体物件、复购、消费反差。每个观察都留来源。
- “从银川到北京”需要原文支持；“买了签证服务”不能写成“签证办下来了”。不猜性别、职业、关系、健康或使用体验。
- 少用“日子有了颜色”“慢慢走答案自会出现”等可放进任何人页面的结尾。可以不升华，也不把所有主题强行写成成长。使用目标账号第一人称须确认原文归属，不能替别人发明内心独白。
- 覆盖范围、接口失败和统计口径进下方说明，不占主总结。证据限定在来源入口说明一次，不在每个主题末尾重复“买过不等于用过”。敏感私密商品不默认放总览、主题或分享，仍可保留在本地原始档案。
- 图片由 Agent 筛选清晰、构图可用、能代表该主题的真实素材；无需为了占满年份把每年的第一张自拍都摆上首页。广告字很多的商品图片降为来源，不默认当主视觉。

### 计划必须先生成，不能空着

Agent 在构建期生成 **3—6条具体、可选、可编辑的建议**，每条关联来源和推荐月份。少资料时可以少于3条，并解释；不能为凑数编造愿望。构建器遇到空计划会停止，不交付空页面。

- 微博：原文明确想做但未完成的事优先；其次根据持续兴趣提出小行动。例：多次记录同一路线的照片，可建议整理一份地点相册；不能捏造“明年旅行”或健康目标。
- 淘宝：优先整理已有物件、核对重复订阅/复购清单、做一份现有材料目录等不强制消费的小事。不把“又买过”写成“应该再买”，不自动定购物预算。
- 每条只写一个动作；依据独立显示。随机指定月份要明示是安排建议，不由购买日推断周期、到期日或消费需求。
- 离线页面不能重新调用模型；建议在构建期写好，页面只负责呈现和编辑。“自动生成”不等于运行时写泛化随机清单。

## 已写好的版式

- **paper**：紧凑双页、居中的纵向书脊、相纸/便签/歌曲、具体节点。没有顶端装订空场，不靠大段 margin 撑版。
- **frosted**：低饱和色域、半透明面板、黄橙高亮、时间线。无缝线、金属环或旧纸。
- **collage**：大短标题、三列独立纸层、不等大的真实物件组合，手机重新排序。不是六张等大电商卡片。
- A：主图＋短记；B：双图对照＋前后文本；C：真实摘句＋图片/解读。没有原话就不造引言，布局也不需要凑齐。
- 日历默认最新**有已收录记录**的月份、默认选有记录的日期；格内有真实缩略图或原文短标题，右侧当日记录。空月份保留真实空态，不为了好看填假日常。跨年搜索，分页展示结果。
- 导航和翻页在正常文档流，无固定底栏叠加。对话框可键盘关闭；来源文本经安全文本渲染，不执行微博或商品标题中的 HTML。
- 计划默认显示已有建议，支持增删改、完成、浏览器保存、JSON导出、合并前备份与恢复；同ID保留当前手动版。旧格式不匹配时先适配，不能静默覆盖。
- 分享PNG是真实的1080×1440画布导出，默认文字/节点版，避免私人照片和精确消费信息泄露，也避免 file:// 图片污染画布。它不假装是参考图的整页截图；若用户另要真实图片版分享，再核权、适配和实测。

## 验收要记录事实

运行原数据检查器和 `node --test scripts/test_framework.cjs`、`python -B scripts/test_build_journal.py`。再实际打开页面检查1440×900、390×844：

1. 总览绑定的是 `overview.text`，不是 `coverage_note`；日期从来源计算，不手填假年份。
2. 主题不用固定大高度、巨量留白或空图占半屏；A/B/C是真的不同排法；长文有展开。
3. 日历首屏有正确年月、真实记录，格子不会撑满一整屏却看不到详情；不同覆盖状态不混成“无记录”。
4. 首次打开计划已显示具体建议；编辑/完成后刷新，导出/同ID冲突导入/恢复均测试；运行时无模型也能用。
5. 页面无横向溢出；导航、翻页、分享不相互遮挡；弹窗外正文不被永久覆盖。用截图与参考图对照，不只看结构检查绿色。
6. 双击 file:// 测试离线，实际下载PNG检查尺寸。只测localhost不能声称双击已验证。

不要自行写“完美”“全部功能通过”。列明已测和未测。模板是可靠起点，不保证模型的内容选择正确，Agent仍须读数据、选图、写回顾与核验。
