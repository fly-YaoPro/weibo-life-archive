# 照片回忆册（测试分支）

适用：用户选定的照片，可由宿主网盘 MCP/连接器取图，也可本地导入。先读[选材与网盘取图](photo-sourcing.md)确定参考图、主题/事件、相册或时段；保留微博原流程，不把网盘能力说明当成实测成功。

## 素材与导入

照片项目放在 Skill 外。先解压到独立目录，保留原文件与文件夹结构；不要让用户为了格式要求逐张改名、手写 JSON 或提前整理完故事。可附一句主题、人物称呼和明确的时间背景。没有补充也先分析，有证据才能推断，不让用户从头替 Agent 标注。

```bash
python scripts/photo_import.py --help
python scripts/photo_import.py --source /工作区/原图 --output /工作区/照片项目 --collection-name 照片回忆册
```

导入依赖 Pillow 解码与转正图片。环境无依赖时如实说明，不静默安装。脚本枚举所有候选，完整解码、保存去除 EXIF 的交付副本、按内容 SHA256 去确切重复；近似图仅标成候选组，不能未经读图自动删掉。坏图、未支持格式和失败路径要在导入回执里列出。原图不动，已有人工 story 不被重跑覆盖。

每张成功导入照片都必须有可显示本地文件。重复、未入选和失败数量分开报告，不能只拿最先加载的 200 张或少量样图宣布完成。

## 日期与来源

- `platform:photos`，`target.collection_id/collection_name`；用照片 SHA256 标识，不编微博 UID、帖子 ID 或原帖 URL。
- `date` 为真实 `YYYY-MM-DD`、`YYYY-MM`、`YYYY` 或 null，`date_precision` 对应 day/month/year/unknown，`date_basis` 为 exif/user_manifest/filename/unknown。只有可核验拍摄日期或用户明确说明可用；文件名日期仅在格式明确、无冲突时使用。
- 文件修改时间、网盘上传日期不等于拍摄日期，不拿来补空。EXIF 无时区不凭空补一个精确拍摄时刻；日历只需其已知日期。
- `created_at` 可为空。月、年或未知日期不落到虚构的 1 号、1 月 1 日；保留日期标签并进入独立照片组，依然可搜索和放进回顾。
- 图片用 user_provided、项目内相对路径和安全来源说明。原始路径映射、导入日志放私有工作区，不进入单 HTML 或分享产物。

详细字段由 `photo_contract.py` 校验。未知不应被校验器逼成伪造；真正的缺图、越界路径或冒充来源仍要阻塞。

照片未指定范围时按本次素材的自然跨度，不默认十年；仅人物已标注相册、宠物、旅行等主题也可成册。用户明确指定范围时保留其范围；越界照片留下并提示确认，不静默删掉。日期全部未知时写“日期待确认”，不包装成某几年回顾。无法读取的目录记入失败，文件数只报可知下界，不宣称已清点完整。

## 读图与写作

以一组照片为分析单位，元数据与画面互相核对。目标是整理出事件及阶段之间的联系，不是给每张图写一句话。

### 元数据搭线索

导入后读取 `.private/photo-metadata.json`（可用时）与日期证据：真实拍摄字段、原有时区、GPS及连续拍摄顺序。索引记录的是文件实际携带的值，不保证相机时钟绝对正确；截图、转存、异常年份或用户说明有冲突时保留疑点，不强行定论。文件夹名也只作线索，除非用户确认。

GPS只在私有工作区帮助归组，缺失时不补造；未经许可不把照片或精确坐标发给第三方识别/逆地理服务。坐标不能自行变成准确地名，识别城市或地标仍需可核查依据。公开页面默认不放精确位置，地点名称由用户确认展示范围。分析完成后，图片交付副本仍去除 EXIF。

### 批量读图归事件

先读 `photo-reading.json` 与 `photo-index.html` 总览，分批覆盖全部成功导入照片，再打开代表图和存疑图的大图核对。联系表便于检索，不替代细节确认。记录 source_id 与实际观察，脚本生成索引不等于自动读懂照片。

结合时间接近、场景与环境、可见人物/宠物、服装和活动连续性形成候选事件；跨年份再找重复地点、同类物件、宠物成长或生活环境变化。时间接近不必然同一事件，同一地点也不必然同一次到访。近似照片只辅助筛选，不自动当作重复删除。

可以标“人物A”“猫”“聚餐”“海边”等可见内容；姓名、具体身份和亲属/恋爱关系只用用户提供的称呼或确认，不靠外貌认人。无法确认同一人物/宠物时也不强行串成一条成长线。

### 事实、推断与确认

在 `.private/photo-analysis.json` 中保留简洁事件底稿，每组写：`source_ids`、可见事实、元数据线索、候选事件/阶段、推断依据与疑点、影响故事的待确认项。无需为每张照片机械填表，也不把这份分析底稿原样放到页面。

- **事实**：画面实际可见、文件确实携带或用户明确提供；写明属于哪种来源。照片上出现蛋糕不等于确定是谁的生日。
- **推断**：允许组合多张图提出有依据的解释，记录依据；不把模型置信度或多张相似图当成事实证明。非关键、低风险的推断可用合适语气写入；身份、关系、毕业、婚礼、搬家等影响整段叙事的定性，先确认或改用中性描述。
- **关键确认**：先完成候选事件和初稿，再一次集中问真正会改变故事的少量问题，如“这组是一次出游还是两次？”“这里应如何称呼？”。已明确提供的信息不重复问；用户纠正日期时采用其说明的原精度，私下保留元数据冲突。没有回复时继续制作有据部分，待确认线索不写成既定经历。

例如，同一周的行李、车窗和海边照片，可以提出“可能属于同一次出游”，用中性的“海边的几天”组织；不能据此认定为“毕业前和最好的朋友最后一次旅行”。

### 从事件写成回顾

用 `themes` 组织事件或阶段，`source_ids` 关联证据，照片主导页面。短文写具体变化、反复出现的小事及用户确认的背景，让相邻章节有联系；不要每张图各写一段，也不要用空泛感慨替代照片细节。可留白、可温暖，不捏造当事人的内心活动。不要求凑满十年，不足按实际跨度。

复用 overview/themes/scene/letter/share：每章用关联照片，不用生成图替代原图。首尾插画只是装饰，照常保留物件标定和实点检查。寄语、下一次一起做的事可以自动给有据建议并允许用户修改，不强塞个人任务面板。合成测试必须在标题、meta.fixture 与图片来源里明确标注，不能当真实案例。

## 构建与共同验收

```bash
python scripts/check_project.py /工作区/照片项目 --kind photos --stage data
python scripts/story_tools.py /工作区/照片项目 index --output /工作区/照片索引.json
# Agent读图并完成 story.json 和所需插画后：
python scripts/journal_run.py --source /工作区/照片项目 --output-root /工作区/照片成品 --build-only
```

至少验证：所有成功照片可显示；确切重复计数正确；未知/年/月日期不串进某天；日历默认打开有内容月份；事件归组有图有据、推断没有冒充事实、关键称呼和经历已确认或保留中性；回顾、原图、日历来源跳转、未来寄语、配乐开关和分享长图可用；桌面与手机无遮挡。私有元数据及分析底稿不进入打包/分享。静态通过不冒充真实用户读图质量或网盘采集验证。

配乐沿用原创/授权/用户提供音源，首次关闭、用户点击后播放，不随便下载商业歌曲。分享页以照片和阶段短记为主，不露原文件路径、定位 EXIF 或未选择照片。

公开分享/部署仍需用户确认上传内容与可见范围。不展示采集过程不等于消除合照隐私风险；先预览、由用户确认愿意展示的照片，再发布。
