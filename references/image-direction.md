# 场景与结尾图设计

首屏不是图片上覆盖一大段文字，而是像温柔探索游戏的记忆入口。先从已收录记录提炼3—5个反复出现或特别重要的**可见物件**，每件有source_ids；依经历选择卧室、家、教室、学校、工作台等最贴合的一个完整空间。动物与宠物仅在记录确有依据时出现。

## 生成两张图

本节仅适用用户选择的可选场景增强。可只做基本回看/日历/计划，不生图也能交付；完整双图模式才需首屏与结尾两张。生成图放decorations，配alt。

1. **记忆场景**：单张**横屏16:9**（适配Web端宽屏查看），平视或轻俯视的完整空间，有柔和自然光、前中后景。核心物件自然分布，留清晰可点击轮廓；不拼成孤立图标清单。桌面阅读区与手机滑动探索时都能认出3—5物件，物件中心尽量在画面10—90%内。**画面中不出现任何人物或人物形象（含全身、半身、剪影、背影、手部等人体部位），只画物件与环境**。标题和准确数据由HTML叠排，不让模型画长文本。
2. **来信结尾**：同一视觉语言，同样为**横屏16:9**，较近的温暖静物构图；将2—4个核心物件、确有依据的宠物、窗光等自然相连。让它像留给未来的一角安稳，避免堆标签或鸡汤标语。**画面同样不出现任何人物或人物形象，只画物件与环境**。独立生成，不直接重复首屏。

使用实际宿主可用、用户允许的生成模型；不绑定特定模型。优先发现目标Harness的专用生成工具，读取实际工具定义和相关Skill；按其真实参数选择模型，核对返回或任务记录中的模型信息，不要冒称使用了未调用的模型。不强制任何工具名、CLI、参数键或Endpoint；开发环境没有生成入口不代表目标Agent也没有。工具不足时记录能力或额度限制；可先完成全部确定性工作，降级遵循用户已给选择，不声称已完成尚未生成的图。

## 固定风格与有据提示词

首屏和结尾保持Trace1的**温暖手绘水彩+彩铅**，透明叠色、纸张纤维、轻微颗粒、奶白/米黄/浅木色、珊瑚红与秋日暖橙、低饱和植物绿或蓝灰远景、柔和斑驳窗光和连贯空间。纸本与磨砂只改变HTML材质，不能把磨砂的生成图改为照片写实。固定正向/负向要求放在[美术资源](../assets/art-direction.json)，每次复用，不临时缩成“温暖风格”。

由Agent从已收录原文准备art-plan.json：space为意象空间；scene_objects和letter_objects为物件数组，每物件有name、source_ids、evidence（原文精确连续子串≥4字符）、placement；literal表示原文直接支持，symbolic另有rationale说明如何象征原文。唱片可象征专辑，但不能声称用户真实拥有这张黑胶。每张1—5件，首尾至少一件相同，依据不足时少放。无字照片/视频封面先实际读图，可设evidence_kind:"image"、image_path与evidence为可见物件观察（visual_evidence亦可），不造原文；路径须属于该原帖真实缓存图。所有证据只写映射，不作为生图指令。

```bash
python scripts/prepare_art_direction.py /工作区/source --plan /工作区/art-plan.json --output /工作区/art-prompts-v1.json
```

脚本离线输出两份prompt、source_ids、objects与style_version，不调用生成工具，不生成替代图。把objects复制到story.scene/letter，首图source_ids用于scene.source_ids，结尾图source_ids用于letter.image_source_ids（来信正文source_ids独立）；再按当前Harness真实工具定义提交prompt，完成后记录实际模型、任务和文件。后续重生成沿用同一style_version；有风格参考能力可将**本次已核验首图**作为结尾参考，不能从Trace带入人物或经历。

通用内容骨架（固定风格段仍由脚本拼入，不把示例写成用户经历）：

> 一个温暖而安静的[有据意象空间]，[物件1]放在[位置]，[物件2]位于[位置]；完整连贯的前中后景。[art-direction.json的固定水彩彩铅风格段]。[对应首屏/结尾构图段与负向要求]。

生成后实际读图：核对无任何人物或人物形象（含本人/亲友、剪影、背影、手部等人体部位）、画幅确为横屏16:9、物件正确、重复/错位、手机可识别度。按**图中实际位置**填0—100坐标；热点必须命中物件，不能只凭提示词猜。模板提供发光呼吸、hover浮层、键盘焦点、点击来源、手机文字目录和明显主入口。

保存到 `decorations/memory-room.webp` / `decorations/next-chapter.webp`。填写scene.alt、letter.image_alt、两图source_ids与真实生成来源（例如独立decorations/provenance.json）。仅将图片路径写入scene/letter，不能混入records.images或证据image_paths。不复刻真实房间、不将参考图人物、原文或无关物件带入用户故事。

标题排版检查：HTML使用均衡换行、严格中文标点规则，不在标题写死br；分享图用实测字体宽度与balancedLines断行，避免孤字尾行、英文单词拆开、闭标点行首和开标点行尾。生成图尽量不含标题，所有准确标题放HTML/代码层；确有图内文字时实际读图逐字检查，出现不合理换行就修改图或排版后重测。

构图安全区：顶部中央约8—15%高度是一行引导的安全区，角落留控件呼吸空间；原图不画标题、按钮或UI。完整原画必须可见；方屏、窄屏与宽屏由模板适配整个画幅和柔和背景，不为铺满而裁掉物件。图与热点统一变换，不能缩图后硬挪热点。轻微视差仍须保持核心画幅和控件可见。

实际读图拒绝：PIL几何色块、低细节占位图、照片写实/塑料3D、首尾色板或笔触突变、无关道具、错误热点、人与人像墙。检查每个对象与原文的关联、画面风格及主体完整度；结构检查通过只证明映射存在，不证明语义或审美。失败则改提示词重新生成，保留回执；能力缺失明确待完成，不能声称高质量图片已生成。

封面主照片优先选择真实素材里清晰的横幅或方图，与开场白/画像共同排版；选择须记录对应source_ids，不为填满框裁掉主体。竖图仍完整适配，可放在后续相册页。

示例的彩铅纸纹、斑驳窗光、前中后景和生活物件是美术方向；不能把参考中的电视、童年、夏天或家庭空间直接当作用户经历。按[场景构图资源](../assets/scene-composition.json)准备画面，物件、空间、文案与热点仍由Agent依据实际记录决定。
